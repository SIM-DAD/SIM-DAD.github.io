Executive Blog Post

Ghostwritten thought leadership on local-first research tools.

By Alex Leith, PhD — Founder, SIM DAD LLC

Every semester, I teach research methods to mass communications undergraduates. The course covers survey design, content analysis, statistical testing — the full arc from question to publication. And every semester, the same moment arrives: the week students try to run their first dictionary-based text analysis.

Some use LIWC. Some try R. A few attempt Python. By Thursday, half the class is stuck. Not because they don't understand sentiment scoring — they do. They're stuck because the tool failed them. A package didn't install. An API key expired. A cloud service flagged their student email as unverified.

The Tool Shouldn't Be the Hardest Part

I started building TASS in 2024 because I was tired of watching capable researchers lose hours to software problems that had nothing to do with their research. The students in my classroom are not computer scientists. They are journalists, strategic communicators and media scholars who need to analyze text as part of their professional training.

They deserve a tool that respects that.

TASS is a desktop application. It installs in minutes. It runs dictionary-based text scoring, group comparisons and correlation analysis without requiring a programming environment, a cloud account or a recurring subscription. Import a CSV, select a dictionary, and the structured output panel shows your results — with effect sizes, confidence intervals and APA-formatted tables ready for your manuscript.

Why Local-First Matters

The decision to build TASS as a local-first application was not a marketing choice. It was an ethical one.

Researchers routinely work with data that carries institutional obligations. Interview transcripts covered by IRB protocols. Student writing samples protected by FERPA. Organizational communications shared under NDA. When that data enters a cloud-based analysis tool, it crosses a boundary that many institutional review boards have not explicitly evaluated.

TASS eliminates the question entirely. Every computation happens on the user's hardware. No data is transmitted after installation. No internet connection is required for any core feature. The analysis that stays on your machine is the analysis your IRB never needs to review.

What's Inside

TASS includes the statistical tests that peer reviewers expect: Welch's t-test, Mann-Whitney U, one-way ANOVA, Kruskal-Wallis with Tukey HSD and Dunn's post-hoc comparisons. Pearson and Spearman correlations. TF-IDF scoring for term weighting. N-gram support for multi-word dictionary entries.

Every output includes assumption checks — Shapiro-Wilk for normality, Levene's for homogeneity of variance — so researchers can justify their test selection. The export engine produces APA-formatted Excel tables and writes a reproducibility metadata sidecar documenting the exact analytical pipeline: which dictionaries, which preprocessing steps, which correction method.

I built these features because I assign them. If I ask my students to report effect sizes and justify their statistical choices, the tool they use should make that easy, not optional.

Built for the Researcher You Already Are

TASS is not a replacement for R or Python. If you write code fluently, you probably don't need it. TASS is for the researcher who knows what a Kruskal-Wallis test is, knows when to use it and just needs a tool that runs it correctly without a two-hour debugging session first.

The 30-day free trial is available at usetass.app. No credit card. No account creation. Install it, open your data and see what your corpus has been trying to tell you.

SEO Memo

Target keywords:

  • "text analysis software" — targets researchers searching for LIWC alternatives. High commercial intent. Used naturally in the opening context and product description sections.
  • "dictionary-based text analysis" — targets the specific methodology TASS supports. Informational intent from graduate students and early-career researchers learning the method. Used in the tool description and "What's Inside" section.
  • "local-first research tool" — targets the privacy-conscious segment. Emerging search term among researchers concerned about cloud data policies. Used in the "Why Local-First Matters" section and closing.

Integration approach: Keywords appear in contexts where a reader would naturally encounter the concept, not as inserted phrases. "Dictionary-based text analysis" describes what the tool does. "Text analysis software" describes what it is. "Local-first research tool" describes why it's different. None disrupt the first-person voice.
